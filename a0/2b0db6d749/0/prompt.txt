## 2. Render &amp; fill flow

### Entry routes

`src/Routers/routes/adminRoutes.tsx` L20-22: `/admin/questionnaire`, `/create`, `/:id/edit` (authoring only).

### Chain

```
route → EncounterQuestionnaire (src/components/Patient/EncounterQuestionnaire.tsx:25)
      → QuestionnaireForm (QuestionnaireForm.tsx:369)
      → QuestionRenderer (QuestionRenderer.tsx:38)   [per top-level question]
      → QuestionGroup (QuestionGroup.tsx:105)        [recursive; enable_when gate]
      → QuestionInput (QuestionInput.tsx:174)        [type switch]
      → &lt;XQuestion /&gt;
```

`EncounterQuestionnaire.tsx` is a thin wrapper: fetches encounter for `PatientHeader` (L34-41), renders the form in a `Card`, and hardcodes post-submit navigation (L68-80).

### Question type → component mapping

`QuestionInput.tsx:234-376`, a single nested `switch`:

- `dateTime`→`DateTimeQuestion`, `date`→`DateQuestion`, `decimal`|`integer`→`NumberQuestion`, `quantity`→`QuantityQuestion`, `choice`→`ChoiceQuestion`, `text`|`string`→`TextQuestion`, `boolean`→`BooleanQuestion`, `time`→`TimeQuestion`, `display`→`null`, default→`TextQuestion`
- `structured` → inner switch on `question.structured_type` (L259-365): `medication_request`, `medication_statement`, `service_request`, `charge_item`, `allergy_intolerance`, `symptom`, `diagnosis`, `appointment`, `encounter`, `time_of_death`, `files`. **Each branch guards on `encounterId`/`facilityId` and returns a raw `&lt;span&gt;{t("..._no_encounter")}&lt;/span&gt;` fallback.**

`commonProps` (L220-232) is the implicit contract every leaf must accept: `{classes, disableRightBorder, question, questionnaireResponse, updateQuestionnaireResponseCB, disabled, withLabel, clearError, index, patientId, errors}` — untyped, spread-based.

### State management

All state lives in `QuestionnaireForm` as plain `useState`; **no context, no form library, no reducer** (verified: zero `createContext`/`useContext` in `src/components/Questionnaire/`).

- `questionnaireForms: QuestionnaireFormState[]` (L381) — array because users can append extra questionnaires via `QuestionnaireSearch` (L1112-1133). Each entry = `{questionnaire, responses, errors}` (L63-67).
- `initializeResponses()` (L334-367) flattens the question tree into a flat `QuestionnaireResponse[]`, seeding `initial_selected` answer options.
- Updates: `onResponseChange` callback inline at L1058-1081 — full `map` over all forms and all responses on **every keystroke**; also clears `errors: []` for the whole form.
- Other state: `isDirty`, `serverErrors`, `activeQuestionnaireId`, `activeGroupId`, `isInitialized`, `draftMismatchError`.
- `enable_when` evaluated in `isQuestionEnabled` (`QuestionGroup.tsx:37-103`), matched by `link_id`; disabled groups clear their descendants' responses in a `useEffect` (L134-138).

### Submission

`handleSubmit` (`QuestionnaireForm.tsx:743-946`) — ~200 lines:
1. Clear errors, run required-field validation + `STRUCTURED_TYPE_VALIDATORS` (L295-332, only 5 of 11 structured types have validators); scroll to first error.
2. Build structured requests via `getStructuredRequests()` (`structured/handlers.ts:270`) — async, `Promise.all`.
3. Append one `POST /api/v1/questionnaire/{id}/submit/` per form (L869), with inline date/dateTime/unit/coding coercion (L888-916).
4. If continuing a draft, append `PUT /api/v1/form_submission/{id}/` with `status: "submitted"` (L929-941).
5. Fire **all** as a single `batchApi.batchRequest` (L422).

**Endpoints hit** (raw URL strings, bypassing the typed api layer):
- `POST /api/v1/questionnaire/{id}/submit/`
- `POST /api/v1/patient/{patientId}/{allergy_intolerance|symptom|diagnosis}/upsert/`

- `PUT /api/v1/encounter/{encounterId}/`, `PUT /api/v1/patient/{patientId}/`
- `POST /api/v1/facility/{facilityId}/slots/{slot_id}/create_appointment/`
- `POST /api/v1/facility/{facilityId}/charge_item/apply_charge_item_defs/`

**Drafts** (`careConfig.enableQuestionnaireDraft`, `care.config.ts:333`): `handleSaveDraft` (L717-741) dumps `questionnaireForms[0]` wholesale into `response_dump.questionnaireResponses`. Only allowed when there are no structured questions and exactly one form (L556-582). Resumed via `?continue_draft=&lt;id&gt;` (L378, L588-639) with an id-equality mismatch guard.

## 5. Pain points visible in the code

**Giant files.** `QuestionnaireEditor.tsx` at 3253 lines contains `LayoutOptionCard`, `OptionFields` (L1496), `QuestionEditor` (L1718) and `getQuestionByPath` (L3247) inline. `MedicationRequestQuestion.tsx` at 2390 lines has ~60 imports pulling in prescriptions, product knowledge, medication statements, templates, and `useCurrentFacilitySilently`. `handleSubmit` alone is ~200 lines.

**Prop drilling.** `patientId`, `encounterId`, `facilityId`, `questionnaireId`, `questionnaireSlug`, `disabled`, `errors`, `clearError`, `activeGroupId` are threaded verbatim through 4 levels (Form → Renderer → Group → Input → leaf). `QuestionGroup` re-passes 12 props to itself recursively (L191-206). `questionnaireSlug` was added purely so `MedicationRequestQuestion` and `ServiceRequestQuestion` could filter templates. `commonProps` (`QuestionInput.tsx:220`) is an untyped spread bag.

**Encounter/facility coupling.** Every structured branch in `QuestionInput.tsx:259-365` conditionally degrades to a bare `&lt;span&gt;` when `encounterId`/`facilityId` are missing — 11 near-identical guard blocks. `structured/handlers.ts:164-168` even `throw`s at submit time if `facilityId` is absent.

**Special-cased structured types.** The same 11 types are enumerated in six places that must be kept in sync: `data/StructuredFormData.tsx:212` (`STRUCTURED_QUESTIONS`), `structured/types.ts:27,42` (two maps), `structured/handlers.ts:34`, `QuestionInput.tsx:259`, `QuestionnaireForm.tsx:295` (`STRUCTURED_TYPE_VALIDATORS` — covers only 5 of 11), and `QuestionRenderer.tsx:17` (`FULL_WIDTH_QUESTION_TYPES`, 3 of 11).

**Imperative DOM.** Error navigation uses `document.getElementById("question-" + id)` plus manual `classList.add/remove` with a `setTimeout(…, 2000)`, duplicated twice inside `ValidationErrorDisplay` (L196-217 and L258-279) and again in `handleSubmit` (L822-825) and `utils.ts:68`.

**"preview" sentinel strings.** `encounterId === "preview"` is checked in `QuestionRenderer.tsx:53` and `QuestionnaireForm.tsx:1106` to suppress submit/search; `patientId="preview"` is passed too. A magic-string mode flag rather than a prop.

**Bypassed API layer.** All submit requests are hand-built URL strings in `handleSubmit`/`handlers.ts` despite typed route objects existing. There's an explicit `TODO` + `eslint-disable @typescript-eslint/no-deprecated` at `QuestionnaireForm.tsx:419-421` about migrating to `useBatchRequest`.

**Dead / half-wired metadata.** `Question.formula`, `read_only`, `is_observation`, `collect_time`, `collect_performer`, `collect_body_site`, `collect_method` are editable in `QuestionnaireEditor` (e.g. L2457-2464) but **no fill-side component reads them** (grep across `QuestionTypes/`, `QuestionRenderer`, `QuestionnaireForm` returns nothing). Correspondingly, `handleSubmit` L917-919 sends `note`, `body_site`, `method`, and `form.ts:49` declares `taken_at`, but nothing except `note` is ever set — `updateQuestionnaireResponseCB` only accepts `(values, questionId, note)`.

**Other smells.** Type-name collision: `QuestionnaireResponse` means two different things in `form.ts` vs `questionnaireResponse.ts`. `handleSubmissionError` (L676-713) pairs server results to forms by **array index** rather than `reference_id`. Draft `response_dump` stores the entire questionnaire definition alongside answers, so any edit to the questionnaire invalidates the draft (mismatch guard at L602). `useNavigationPrompt` is disabled in dev (L586).
