## 4. What to build (per §7 of the design doc)

### Phase A (complete and verified first)
- **Types and API definitions:** add `src/types/abdm/abdm.ts` and `src/types/abdm/abdmApi.ts` (or equivalent per repo conventions) covering all §6 endpoints.
- **Config gating:** gate everything on `GET /api/v1/abdm/config/` returning `enabled`. When disabled, CARE behaves exactly as before.
- **Reusable ABHA identify flow** (Sheet or Dialog with steps):
  - **Identifier choice:** ABHA number, ABHA address, mobile or Aadhaar. Keep the choice of identifier separate from the choice of auth method (Aadhaar OTP or mobile OTP) for ABHA number and ABHA address.
  - **Find ABHA by mobile:** show the masked list, pick an entry, choose an OTP method, then the OTP step.
  - **OTP step:** show the masked mobile from the server, a 60 s resend countdown and at most 2 resends, both driven by the server's `resend` object.
  - **Account chooser:** when the response has `status=select_account`.
  - **Not-found path:** only on `abha_not_found`. Title it for both outcomes, then go to creation via Aadhaar:
    - Show the verbatim consent text from `config.consent.text` and require an "I agree" checkbox before ANY Aadhaar is sent, for both login and create.
    - Reuse the Aadhaar and consent already given (never ask twice). For non-Aadhaar identifiers, still look up by Aadhaar first; create only after a second `abha_not_found`.
  - **Create steps:**
    1. OTP plus mobile.
    2. Mobile OTP, only if `mobile_verification_required`.
    3. ABHA address: suggestions or a custom value with the `@{cm_id}` suffix; skippable if an address already exists.
  - **Result:** a profile card (photo, name, gender, DOB, ABHA number, address, mobile, KYC badge) with download-ABHA-card and show-QR (base64 from the API), plus the primary action of the placement.
  - **"Not now" / "Continue without ABHA"** exits.
  - **Inline errors** on the current step. Never blame the patient. Mask the Aadhaar to its last 4 digits after entry. Client-side validation: Aadhaar is 12 digits with a Verhoeff check; mobile is 10 digits starting 6–9; ABHA number is 14 digits, with or without hyphens.
- **Registration (create mode):** an ABHA step before the form.
  - On success, prefill the form from `AbhaProfile`. Lock name, DOB/year of birth and gender when `kyc_verified`. Show a "from ABHA" provenance marker on prefilled fields.
  - Phone, address, pincode and best-effort state/district geo organisation stay editable.
  - On submit, create the patient as today, then call `POST /api/v1/patient/{id}/abha/link/` with the `transaction_id`. If the link fails, keep the patient and show a toast.
  - If `existing_patient` is set, show it and offer "Open patient" when `can_view`. Block duplicate registration for that ABHA.
- **Patient page ABHA section** (replace the commented block in Demography.tsx):
  - **Linked:** show number, address, KYC, source, and linked by/at. Actions:
    - Show ABHA card: run the identify flow prefilled with the linked ABHA number, then fetch the card and QR.
    - Update mobile: verify first, then mobile OTP via `profile/mobile/*`.
    - Unlink, with a confirmation.
  - **Not linked:** "Link ABHA" runs the identify flow, shows any demographic differences, then links on confirmation.
- Add all strings to `public/locale/en.json`.
