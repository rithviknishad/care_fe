`Broken` — an unvalidated URL param is used as a computed key into the API request.

`searchWith` is `qParams.with`, i.e. arbitrary user-controlled text from the URL. Spreading it as `{ [searchWith]: searchValue }` here places it *after* the `buildQueryParams(...)` spread and after `encounter_class`, so `?with=encounter_class&value=x` (or `status`, `priority`, `organization`, `created_date_after`) silently overrides a filter the rest of the UI still displays as set. The old code could only ever write `name` / `external_identifier`.

The deleted `SearchWith` 
union was what made that impossible. Narrow it back at the read site 
rather than at the write site — e.g. derive from the options list you 
already have:

```
const searchWith = searchWithOptions.find((o) => o.key === qParams.with)?.key;
```

`PopoverAnchor asChild` clones `CommandInput`, and `CommandInput` spreads its props (including the forwarded ref) onto the **inner** `CommandPrimitive.Input`, not onto its outer `data-slot="command-input-wrapper"` div. So the popover anchors to the bare input, which is inset by the wrapper's `px-3` and the search icon — `--radix-popover-trigger-width` on `PopoverContent` will therefore be narrower than the visible field and offset to the right of it.

If you want the dropdown to line up with the field, wrap the input in a plain element and anchor that instead:

```
<PopoverAnchor asChild>
  <div className="relative">
    <CommandInput ... />
  </div>
</PopoverAnchor>
```

`Broken` — every keystroke goes to the URL, and `updateQuery` forces `page: 1`.

`updateQuery` (`src/hooks/useFilters.tsx`) does `filter = { page: 1, limit, ...filter }`,
 so typing one character in the search box resets pagination. A user on 
page 4 who edits an existing search silently jumps back to page 1 
mid-word. It also rewrites the query string per character; `query.debounced` spares the network but not the re-render/history churn.

Also note this makes the search live-on-keystroke, which 
contradicts the draft-until-Enter UX described earlier in this PR — the 
Enter branch below now only fires when the field is empty. If live 
search is the intended behaviour that's fine, but say so; if not, the 
draft value needs to stay local.
